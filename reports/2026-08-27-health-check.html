F-05 robots.txt declares two wildcard groups; the /admin rule may be ignored WarningMedium
Category
SEO and Search Visibility
Observed
The Cloudflare-managed block opens with User-agent: * / Allow: /. A second, separate User-agent: * group follows at the end of the file carrying Disallow: /admin and the Sitemap: line.
Notes
Under RFC 9309 a crawler selects the single most specific matching group, so the trailing Disallow: /admin may never be applied. The Sitemap: directive is group-independent and is unaffected. This is a crawl-directive defect, not an access control — robots.txt never protects an admin path in the first place.
Action
Merge into a single User-agent: * group so Disallow: /admin sits alongside Allow: /. Confirm /admin is protected by authentication independently.
Owner
Web development team

This cycle was run at the owner's direction against their own property, using a health-check user agent at low request volume — not as ClaudeBot. It should be a conscious decision before this runs on a schedule.

No forms were submitted, no records created, and no content, DNS or configuration was modified. Form validation was exercised with checkValidity(), which validates locally and sends nothing.
